# Data retention and deletion

| Data | Retention | Mechanism | Deletion path |
| --- | --- | --- | --- |
| Uploaded datasets & records | Until deleted by an owner | store array | `DELETE /api/datasets/[id]` (owner) — removes records with it |
| Player records from demo seed | Regenerated by `npm run seed` | `seed.ts` | `npm run seed` replaces the workspace |
| Saved reports | Until deleted; references datasets | `reports[]` | reports API delete (owner) |
| Shortlists | Until deleted | `shortlists[]` | shortlists API |
| Feedback messages | Newest 5,000 | store trim on insert | request via contact form; owner can close/delete in Postgres phase |
| Contact-form IP | Never stored raw — only `hash:xxxxxxxxxxxx` | `ipHint()` | n/a |
| Audit entries | Newest 2,000 | store trim | not user-deletable by design (governance) |
| AI usage entries | Newest 5,000 | store trim | not user-deletable (cost governance) |
| Sessions | 12 h default (`SESSION_MINUTES`) | expiry timestamp | logout deletes |
| Notifications | Newest 200 | store trim | — |
| Testimonials | Until removed | `DELETE /api/testimonials?id=` | owner |
| Analytics (GA4) | Per Google's retention setting (your property) | outside the app | Google Analytics admin |
| Backups | Per hosting/provider policy | outside the app | provider console |

## Rules

1. **No soft deletes for datasets.** Deleting a dataset removes its records; reports that
   referenced it keep their saved text and mark the source as removed.
2. **Audit is append-only** and is never trimmed by user action. It is capped so a single
   workspace cannot grow without bound.
3. **Uploaded files** live on disk today (`DATA_DIR`) and move to object storage in phase 3; the
   deletion endpoint removes both the metadata and the stored file.
4. **Deletion requests** from the public arrive through the contact form (`deletion-request`
   category) and are actioned against the application store; provider backups follow the
   provider's schedule, which the app cannot control — stated in the privacy policy.
5. **Verification.** After any deletion implementation, reconcile counts: `datasets`,
   `dataset_records`, files on disk, and exported reports referencing the dataset.
