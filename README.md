# Universal AI Cricket Intelligence, Analytics, Scouting & Auction Strategy Platform

**Project structure & scaffold package** — generated from an inspection of the existing,
working application. Version `1.1.0-structure`.

This archive is *not* a second copy of the app. It is the professional folder architecture,
the missing configuration/scaffolding and the full technical documentation set for the
existing Universal Cricket Intelligence Platform (UCIP), organised for a hybrid deployment:
**Next.js on Vercel · FastAPI on Render · PostgreSQL/Supabase · object storage**.

## 1. Read this first: what is real, what is scaffold

The platform already runs. It is a Next.js 14 (App Router) application with a deterministic
analytics core, 44 API routes, 29 pages, 151 TypeScript tests, 11 Python tests and a
58-check end-to-end smoke suite. Everything in this archive is labelled with one of three
statuses so nothing is overstated:

| Status | Meaning | Count in this package |
| --- | --- | --- |
| **EXISTS** | Already implemented in your repository. This package documents it and gives its real path — no duplicate code is shipped. | 300+ source files referenced, 0 copied |
| **NEW** | Generated by this package: real starter code, config or documentation you can merge. | ~120 files |
| **PLANNED** | Folder reserved with a scope note and acceptance criteria. No implementation claimed. | tagged inside each area README |

The authoritative path-by-path mapping is **[`MIGRATION_MAP.md`](MIGRATION_MAP.md)**, and the
machine-readable version is **[`PROJECT_STRUCTURE.json`](PROJECT_STRUCTURE.json)**.

## 3. The Rajasthan Royals 2027 scouting workspace

The workspace ships with **Rajasthan Royals configured as the user team** (`isUserTeam: true`
in `lib/core/db/seed.ts`, colours `#E8C15C`), and the talent module carries the
*IPL 2027 — uncapped domestic brief* preset used by the SupeRR Selector Season 2 brief:

* `/talent` — age-banded, uncapped-eligible discovery with headroom weighting and a
  sensitivity report.
* `/auction` — purse position, bid ceilings by role, seeded virtual auction room.
* `/xi` — constraint-satisfying XI (overseas limit, keeper, 20-over bowling plan).
* `/reports` — the `talent` builder produces the 10-player shortlist with policy caveats.

Player names, ages and statistics in demo mode are **synthetic** and labelled `DEMO`
everywhere. Real data must be uploaded and approved in `/data`. See
[`docs/user-guides/RR_SCOUTING_WORKSPACE.md`](docs/user-guides/RR_SCOUTING_WORKSPACE.md).

```
├── scripts/                development · deployment · database · testing · maintenance
├── tests/                  unit · integration · e2e · performance · security · fixtures
└── .github/workflows/      ci · security · release
```

**Why `frontend/` and `backend/` are thin:** your Next.js App Router application *is* the
frontend and most of the backend (route handlers). Copying `app/`, `lib/` and `components/`
into `frontend/src/` would create two sources of truth. Instead:

* `frontend/` contains the **layer map** (`README.md`), the **missing public-asset folders**,
  the **component taxonomy** (which real file belongs to `components/players/`, etc.), the
  **16 feature folders** with scope + acceptance criteria + implementation pointers, and
  small `config/constants/utils` starters that do not exist yet.
* `backend/` is genuinely new: the current Python footprint is two files
  (`services/analytics/app/{main,compute}.py`). `backend/` is the deployable FastAPI
  expansion (settings, logging, CORS allow-list, health, request-id, error envelope,
  statistics router, worker, tests) that Render can host.

The physical move of `app/ lib/ components/` under `frontend/src/` is a **planned phase-2
refactor** (`ROADMAP.md` → Phase 5) with a reversible checklist — not something this package
pretends to have done.

## 8. Honest limitations

* Demo data is synthetic and labelled `DEMO`. Uploaded data is labelled `UPLOADED`; model
  output is labelled `MODEL`. No official league feed is bundled.
* AI narration needs your own provider key; deterministic fallback otherwise.
* Spam CAPTCHA needs your Cloudflare Turnstile keys; rate-limit + honeypot are always on.
* Analytics needs a GA4 measurement ID, and only loads after consent.
* Testimonials ship as three labelled *sample* rows — never as real endorsements.
* Edge TLS/HSTS termination, backups and search-console verification are hosting settings,
  documented but not something an application can do for you.
* `backend/` and the `frontend/src/**` taxonomy are scaffolding: they compile and are
  documented, but the running application does not depend on them yet.

See [`FILES_TO_IMPLEMENT.md`](FILES_TO_IMPLEMENT.md) for the exact remaining work.
